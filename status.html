Status

Netherrack is in early development. This page is the honest version of “what works” — kept in step with the checklist in the project’s README.

Alpha software - don’t rely on it yet

Expect missing features, bugs and glitches. Keep independent backups of any world you care about, and don’t use Netherrack for a world with important data, or expose it to the internet unsupervised.

Currently implemented

  • ✅ Java/Maven project
  • ✅ Server startup and shutdown lifecycle
  • ✅ server.properties configuration
  • ✅ Console command handling
  • ✅ Colored console logging
  • ✅ Linux support/testing
  • ✅ RakNet networking
  • ✅ Bedrock protocol integration
  • ✅ Basic Bedrock login handling
  • ✅ Initial block system
  • ✅ Grass block
  • ✅ Cobblestone block
  • ✅ Chunk loading and generation
  • ✅ Client connection to a Bedrock client
  • ✅ Persistent world storage

Not implemented yet

  • ⬜ Complete world system
  • ⬜ Complete Bedrock play/login flow
  • ⬜ Entity system
  • ⬜ Plugin API
  • ⬜ More blocks and gameplay features

Known limitations

Beyond the missing features above, a few things that exist are worth knowing the edges of:

  • One Bedrock version. Netherrack targets Bedrock protocol 2193 (Minecraft 1.26.50). A different client version can still connect — the server warns and continues — but may not behave correctly.
  • online-mode isn’t enforced. It’s written to server.properties, but Netherrack doesn’t currently require Xbox Live authentication. A player who isn’t signed in can still join.
  • difficulty isn’t applied. The world currently always runs on Easy, regardless of this setting.
  • No whitelist. server-whitelist has a message configured for it in netherrack.yml, but there’s no whitelist system to show it yet.
  • No plugin API. Extending the server currently means changing its source code.
  • No terrain generation. World content comes from the flat presets, or nothing at all (level-type=default).

None of this is hidden on purpose — Netherrack is young, and this list will shrink over time. If you hit something not covered here, open an issue.

What hasn’t been tested

From the v0.1.0-alpha release notes, these haven’t been put through their paces yet:

  • Stability under prolonged use.
  • Performance with many simultaneous players.
  • Shutdown behavior under every possible condition.
  • World persistence after a crash or a forced process kill.
  • Compatibility with every Bedrock client version.
  • Every gameplay mechanic and block interaction.
  • Behavior under heavy chunk loading.

This list isn’t exhaustive either. If you find something, a bug report with your /version output and console log genuinely helps — see reporting a bug.
