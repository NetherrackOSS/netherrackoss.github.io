Status

Netherrack is in early development. This page is the honest version of “what works” — kept in step with the Current status section in the project’s README.

Beta software - don’t rely on it yet

Expect missing features, bugs and glitches. Keep independent backups of any world you care about, and don’t use Netherrack for a world with important data, or expose it to the internet unsupervised.

Currently implemented

  • ✅ Java/Maven project
  • ✅ Server startup and shutdown lifecycle, with version, git commit and GPL reporting
  • ✅ server.properties and netherrack.yml configuration
  • ✅ Customizable per-level console formats and colors, plain log files and /reload
  • ✅ Linux support/testing
  • ✅ NetherNet networking, persistent server identity and Xbox token authentication
  • ✅ Bedrock 1.26.60 protocol integration (protocol 2225)
  • ✅ Basic Bedrock login handling
  • ✅ Inventory and crafting: 2×2 grid, right-clickable 3×3 table, shift-click stack crafting and all 4,770 recipes
  • ✅ Initial block system: breaking, placing, drops and middle-click pick block
  • ✅ Generated terrain (hills, valleys, lakes and trees) and nine flat world presets
  • ✅ Chunk loading and generation, with autosave every 30 seconds
  • ✅ Persistent world storage (LevelDB)
  • ✅ Health, hunger and damage: falls, lava, fire, drowning, starvation and the void
  • ✅ Eating food
  • ✅ Player-versus-player combat with reach, weapon damage, knockback and invulnerability ticks
  • ✅ Item entities: dropped items, death drops when a player dies, and items burning in lava or fire
  • ✅ Commands: help, version, gamemode, give, clear, kill, kick, tp, op, deop, whitelist, reload, plugins, stop
  • ✅ Operators and permission levels
  • ✅ Whitelist: white-list, whitelist.json and the /whitelist command
  • ✅ Plugin API: lifecycle, events, commands, scheduler, permissions, simple forms and a small player/world/block API
  • ✅ Example Maven plugin and plugin API version in /version

Not implemented yet

  • ⬜ Complete world system
  • ⬜ Complete Bedrock play/login flow
  • ⬜ Mobs and a full entity system
  • ⬜ Runtime plugin enable, disable and reload
  • ⬜ Furnace, stonecutter and smithing screens
  • ⬜ Caves, ores, flowers and multiple biomes in generated terrain
  • ⬜ More blocks and gameplay features

Known limitations

Beyond the missing features above, a few things that exist are worth knowing the edges of:

  • One Bedrock version, one transport. Netherrack targets Bedrock protocol 2225 (Minecraft 1.26.60) over NetherNet, the transport the game has used since that release. The protocol has to match exactly, so clients on other versions — or anything still speaking RakNet — can’t connect.
  • online-mode isn’t read as a toggle. It’s generated in server.properties, but Xbox authentication comes from NetherNet and login-chain validation. Don’t rely on the file setting alone to control who may join.
  • difficulty isn’t applied. The world currently always runs on Easy, regardless of this setting.
  • No day-night cycle. The day cycle is frozen: the sun stays where it is and the world never darkens.
  • Plains-only terrain. Generated worlds have no caves, ores, flowers or multiple biomes yet.
  • Some screens are missing. Furnace, stonecutter and smithing screens aren’t implemented.
  • Client movement isn’t validated. Positions are currently accepted as the client reports them.
  • Plugins need a restart. Runtime plugin enable, disable and reload aren’t implemented; a jar change needs a server restart.
  • Plugin command suggestions can lag. API permission changes take effect when a command runs, but a player’s already-sent suggestions aren’t refreshed until the server sends them again.
  • Some vanilla data predates 1.26.60. A few newer blocks or entities may be missing or appear as the unknown-block texture.

None of this is hidden on purpose — Netherrack is young, and this list will shrink over time. If you hit something not covered here, open an issue.

What hasn’t been tested

From the v0.4.0-beta notes, the current README and earlier release notes, these haven’t been put through their paces yet:

  • Long-term stability, performance with many simultaneous players, and shutdown behavior under every possible condition.
  • World persistence after a crash or a forced process kill.
  • Compatibility with every Bedrock client version.
  • PvP hit registration, knockback feel and deaths with a real client.
  • Crafting with a real client: recipe book entries, previews and results.
  • Death drops landing in unloaded chunks or in the void, or dying while flying or with a chest-like screen open.
  • Burning dropped items and their flame animation with a real client.
  • Whitelist enforcement, operator bypass and /whitelist with a real client.
  • Every gameplay mechanic and block interaction.
  • Behavior under heavy chunk loading.
  • Plugin behavior beyond the plain-Java API checks, and runtime plugin changes (which require a restart).

This list isn’t exhaustive either. If you find something, a bug report with your /version output and console log genuinely helps — see reporting a bug.
