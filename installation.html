Installation

Get a Netherrack server running on your own computer.

Requirements

  • Java 17 or newer. Run java --version to check. A JRE is enough to run Netherrack; you need a JDK only to build it yourself.
  • Minecraft: Bedrock Edition 1.26.60. Netherrack currently speaks that one protocol version, and only over NetherNet, the transport Bedrock uses since that release. Older clients (and anything expecting RakNet) will not be able to connect.
  • Port 19132 free for NetherNet’s HTTP signaling and WebRTC game traffic. That’s the default; you can change it in server.properties. Check both TCP and UDP in your firewall. If you also run Bedrock Dedicated Server on this machine, it uses the same port.

The NetherNet native WebRTC library is bundled in the JAR, so there’s nothing extra to install. Netherrack is mainly tested on Linux. It’s plain Java, so it should run anywhere Java 17+ does, but expect rough edges on other systems.

Download

  1. Open the Releases page on GitHub and download the latest netherrack.jar.
  2. Create a folder for your server, for example netherrack-server, and move the JAR into it.
Run it from the server folder

Netherrack creates its files in the folder you start it from, so always cd into the server folder first. Starting it from somewhere else makes a second, separate server there.

Run it

Open a terminal in the server folder and run:

java -jar netherrack.jar

When it starts you should see something like this:

[21:26:00] [main] [INFO] Netherrack is distributed under the GPL License
[21:26:00] [main] [INFO] This is an early build; the plugin API is experimental.
[21:26:01] [main] [INFO] Preparing spawn area...

The version, commit, timestamps and thread names are examples; the commit is build-specific and may show unknown outside a git checkout. Once you see Done!, the server is ready for players. Type help in the console for the list of commands.

Native-access JVM flags

If the NetherNet native transport reports memory-access or native-access errors, launch the server with:

java --sun-misc-unsafe-memory-access=allow --enable-native-access=ALL-UNNAMED -jar netherrack.jar

The repository also includes start.sh and start.bat, which pass those flags and expect the JAR to be named netherrack.jar in the same folder. The --sun-misc-unsafe-memory-access=allow flag is not recognized by older JVMs such as Java 21; if a script fails with Unrecognized option, use java -jar netherrack.jar unless your platform actually needs the flags.

The first run

The very first time, Netherrack sees there’s no server.properties and starts a short setup wizard:

  1. Language. Type en-US (English) or pt-BR (Brazilian Portuguese), or press Enter for English.
  2. License. Netherrack shows the GNU GPL v3.0 notice and asks Do you accept the license? (y/N):. Type y (or yes; s/sim also work) to accept. Anything else exits startup — the server can’t start without accepting the license.
  3. Setup. Choose whether to answer the remaining questions. Press Enter to use defaults, or answer n to configure them.
  4. Core settings. Enter the server MOTD, port, default gamemode (0 Survival, 1 Creative, 2 Adventure or 3 Spectator) and maximum player count. Press Enter at any prompt to keep its default.
  5. Review. Check the local and external addresses, then press Enter to start. The external address uses a short public IP lookup; if it fails, the wizard says it wasn’t detected.

The extra questions only appear in an interactive terminal. If you pipe input to the server, they are skipped and the defaults are used, so console commands aren’t consumed as answers.

The wizard only runs when server.properties is missing, so you’ll see it once. Afterwards Netherrack creates these in the folder you ran it from:

File or folderWhat it’s for
server.propertiesMain settings: port, player limit, world name, language… See Configuration.
netherrack.ymlNetherrack’s own settings: logging formats and colors, debug options, messages and the flat preset.
permissions.jsonWho is an operator, by Xbox Live ID.
nethernet-identity.pemThe private key Netherrack identifies itself with on NetherNet. Generated once on first start; deleting it makes the server create a new identity, and clients may then treat it as a different server.
worlds/Your worlds. Each is a folder named after level-name, holding level.dat, levelname.txt and a db folder.
plugins/Plugin jars and each plugin’s data folder. Netherrack creates this folder on first start; see Plugins.
logs/latest.logA plain-text copy of the console for the current run.

Stopping the server

Type stop in the console. Netherrack disconnects players with the configured messages.server-shutdown message, disables plugins, saves the world and exits. It also saves the world if you press Ctrl+C or close the console window, and autosaves every 30 seconds while it runs.

Players can run /stop in chat too, but only with permission level 4 — see permissions.

Updating

  1. Stop the server and back up your worlds folder.
  2. Replace netherrack.jar with the new release.
  3. Start the server as before. Your configuration files and worlds stay where they are.
It’s experimental beta software

Netherrack is still changing quickly, and a newer version may not be able to read a world saved by an older one. That’s why the backup comes first.

Build it from source

You’ll need Git and a JDK (Java 17 or newer). The project includes the Maven wrapper, so you don’t need to install Maven.

Linux and macOS 
git clone https://github.com/NetherrackOSS/Netherrack.git
cd Netherrack
bash mvnw clean package
Windows 
git clone https://github.com/NetherrackOSS/Netherrack.git
cd Netherrack
mvnw.cmd clean package

The shaded, runnable JAR is written to target/netherrack.jar. The first build downloads the dependencies, so it needs an internet connection.
