Guides

Short, practical walkthroughs for things you’ll want to do once the server is installed.

Joining from Minecraft

  1. Make sure the server is running — you should see Done! in its console.

  2. On the device running Minecraft, open Play → Servers → Add Server.

  3. Set the Server Address to the computer’s IP address (localhost if Minecraft is on the same computer), and the Port to the one in server.properties (19132 by default).

  4. Save, then tap the server to join.

Only one Bedrock version

Netherrack currently speaks Bedrock protocol version 2225 (Minecraft 1.26.60) specifically, over NetherNet. The protocol has to match exactly, so clients on other versions can’t connect.

Choosing a world type

Pick this before the world is first created — a level keeps the type and preset it started with, and changing the settings afterwards has no effect on it.

  1. Stop the server if it’s running.

  2. In server.properties, set level-type=flat for a flat world, or leave it as default for generated terrain — hills, valleys, lakes and trees, new every seed.

  3. For a flat world, open netherrack.yml and set level.preset-type to one of the preset names, for example "The Void".

  4. If a world with that level-name doesn’t exist yet, start the server and it’s created with that preset. Generated terrain worlds search outward from the origin for dry ground to spawn on.

Want an existing world again?

If you want to go back to a world you’ve used before, set level-name to its name instead. Netherrack loads it as it is; level-type and the preset are only used when creating a new one.

Starting a fresh world

To begin again without losing the old one:

  1. Stop the server.

  2. In server.properties, change level-name to a new name, for example world2.

  3. Start the server. Since no folder with that name exists in worlds, a new world is created there, built from whatever level-type (and preset, if flat) you have set.

Your old world is untouched in worlds/<old-name>/. Switch back to it any time by setting level-name back.

Backing up a world

  1. Stop the server. Copying files while it’s writing to them can corrupt the copy.

  2. Copy the whole worlds/<level-name>/ folder somewhere safe.

To restore it, stop the server, replace the folder with your backup, and start it again.

Back up before updating

Do this before installing a newer Netherrack build, especially while it’s in beta — see Updating.

Making the first operator

New players start at the level in default-player-permission-level (member by default). Visitors and members can run only level-0 commands; operators get the level in op-permission-level (2 by default), which unlocks /gamemode, /give, /clear, /kill, /kick and /tp. To promote someone:

  1. Have them join the server, so Netherrack knows their Xbox Live ID.

  2. In the server console, run:

    op PlayerName

  3. They’re now an operator, and it’s saved in permissions.json for next time. /deop <player> undoes it.

Since you’re running the console, there’s no permission-level requirement here — the console is always allowed to run /op. More on this in permission levels.

Changing the console language

  1. Stop the server.

  2. In server.properties, set language to en-US or pt-BR.

  3. Start the server. The console, including chat log lines and command replies, uses that language from then on.

This only changes the server’s own messages. Each player’s Minecraft client always shows the game itself in whatever language that client is set to.

Installing a plugin

  1. Build or download a plugin jar. Plugins use Java 17+ and declare api-version: 0.4.0 in plugin.yml.

  2. Stop the server and copy the jar into the plugins/ folder next to netherrack.jar.

  3. Start the server. Look for Loaded plugin <name> v<version> in the log, then run /plugins to see the list.

A plugin’s first start creates plugins/<name>/config.yml when it saves its defaults. Runtime plugin enable, disable and reload are not supported yet, so restart after adding, removing or updating a jar. The full API and Maven coordinates are on the Plugins page; the server repository also includes an examples/hello-plugin project.

Reloading logging

  1. Edit logs.debug, logging.* or labels.* in netherrack.yml.

  2. Run /reload (alias rl, permission level 4) in the console or chat.

  3. Check the console and logs/latest.log. DEBUG lines stay out of the console unless logging.console-debug: true, and per-level *-enabled keys hide lines on the console without removing them from the log file.

/reload only re-reads logging settings; most other options still need a restart, and plugin jars are never reloaded at runtime.

Letting friends connect over the internet

By default the server is only reachable on your local network. To open it up further:

  1. Forward port 19132 (or whatever you set server-port to) on your router to the computer running Netherrack. NetherNet uses HTTP signaling and WebRTC game traffic, so check both TCP and UDP.

  2. Share your public IP address (and the port, if you changed it) with the people you want to join.

Experimental beta software, open to the internet

Netherrack hasn’t been hardened for public, unsupervised access — see known limitations. The online-mode key is ignored as a toggle; authentication comes from NetherNet and login-chain validation. Only do this with people you trust, and keep backups.
