Configuration

Everything Netherrack reads is in plain text files next to the JAR. Stop the server before editing most settings — they are read at startup. The logs.debug, logging and labels sections in netherrack.yml can be applied without a restart with /reload.

Files and folders

File or folderWhat it holds
server.propertiesThe main settings, below. Netherrack writes it with comments explaining each one.
netherrack.ymlNetherrack-specific settings: logging formats and colors, debug options, messages and the flat preset.
permissions.jsonThe operators, by Xbox Live ID.
whitelist.jsonThe players allowed in when white-list is on.
banned-players.jsonBanned players, their reasons and who banned them.
nethernet-identity.pemThe server’s NetherNet identity, created on first start. Leave it alone — losing it changes how clients recognize the server.
players/One <uuid>.json identity file per player, following Nukkit’s player-data layout. Used by the plugin API’s offline-player lookup; see below.
worlds/<level-name>/A world: level.dat, levelname.txt and a db folder (LevelDB), in the same layout Bedrock uses. Player data is saved with it.
plugins/Plugin jars and their generated data folders, each usually holding a config.yml. See Plugins.
logs/latest.logThe console, in plain text, for the current run. It’s overwritten each time the server starts — copy it first if you need it.

netherrack.yml

Settings that belong to Netherrack rather than to the Bedrock file format. Values can be plain or quoted, and # starts a comment.

netherrack.yml (without the comments Netherrack adds) 
logs:
  debug: false

logging:
  format: "[{time}] [{thread}] [{level}] {message}"
  info-format: "[{time}] [{thread}] [{level}] {message}"
  warn-format: "[{time}] [{thread}] [{level}] {message}"
  error-format: "[{time}] [{thread}] [{level}] {message}"
  debug-format: "[{time}] [{thread}] [{level}] {message}"
  prefix: ""
  suffix: ""
  time-format: "HH:mm:ss"
  date-format: "yyyy-MM-dd"
  colors: auto
  console-debug: false
  info-enabled: true
  warn-enabled: true
  error-enabled: true
  debug-enabled: true

labels:
  timestamp-color: "cyan"
  thread-color: "yellow"
  info-color: "blue"
  warn-color: "red"
  error-color: "bright-red"
  debug-color: null
  bracket-color: null

messages:
  server-shutdown: "Server closed"
  server-online-mode: "You must be signed into Xbox Live to join this server!"
  server-whitelist: "You are not whitelisted on this server!"
  server-ban: "You are banned!"

level:
  preset-type: "Classic Flat"

logs.debugfalseWrites every packet and other Netty debug detail to logs/latest.log, not the console. The log grows quickly. Reloadable with /reload.
logging.info-format, warn-format, error-format, debug-format[{time}] [{thread}] [{level}] {message}Console pattern for each level. Placeholders are listed below.
logging.formatsame default patternFallback for any level without its own format.

logging.console-debugfalseShows DEBUG lines on the console using debug-format. They stay in the log file either way.
logging.<level>-enabledtrueHides a level on the console without removing it from the log file.

Formats accept {time}, {date}, {millis}, {thread}, {level}, {message}, {prefix} and {suffix}. An inline <name> inserts a color, a style (<bold>, <italic>, <underline>, <reset>) or one of those same values; <null> inserts nothing. For example: [<yellow>{time}] <bold>{level}<reset> {message}.

Label colors are names such as red, yellow, blue, gray and the bright- variants, plus purple/grey aliases. Hex values such as #ff8800 and raw escapes like "\u001B[36m" work too. Missing keys fall back to the defaults above, and malformed settings are warned about and ignored. These sections are read before the first startup line; /reload reapplies them. Console formatting never changes logs/latest.log, which keeps the plain default shape.

Flat world presets

Set level-type=flat in server.properties, then name a preset in level.preset-type in netherrack.yml. The names match the ones Minecraft shows in its world-creation screen.

PresetLayers, from the bottom up
Classic Flat1 bedrock, 2 dirt, 1 grass block
Tunneler's Dream1 bedrock, 230 stone, 5 dirt, 1 grass block
Water World1 bedrock, 64 deepslate, 5 stone, 5 dirt, 5 gravel, 90 water
Overworld1 bedrock, 59 stone, 3 dirt, 1 grass block
Snowy Kingdom1 bedrock, 59 stone, 3 dirt, 1 grass block, 1 snow layer
Bottomless Pit2 cobblestone, 3 dirt, 1 grass block
Desert1 bedrock, 3 stone, 52 sandstone, 8 sand
Redstone Ready1 bedrock, 3 stone, 116 sandstone
The VoidNo layers. Players start on a 33×33 stone platform at the bottom of the world.
Presets only apply to new worlds

A world keeps the type it was created with. Changing level-type or the preset has no effect on a world that already exists — see the guide to choosing a world type.

permissions.json

A list of operators, each identified by their Xbox Live ID (XUID) — a player’s name can change, their XUID can’t. You normally don’t edit this by hand: the /op and /deop commands change it for you. If the file doesn’t exist, Netherrack creates an empty one.

permissions.json (the XUID is just an example) 
[
  {
    "permission": "operator",
    "xuid": "2535400000000000"
  }
]

Entries can also set visitor or member for a player, overriding their default level. Plugin permission nodes are separate: plugins register them in code and can allow or deny them per player or the console. Players who aren’t signed into Xbox Live have no XUID, so they can’t be made operators.

whitelist.json

The optional player allowlist, used only when white-list=true in server.properties. An entry can name a player by gamertag, Xbox Live ID (XUID), UUID, or any combination of those. Adding an online player with /whitelist add saves all three where available, so the entry keeps working after a gamertag change; an offline player can be added by name alone. Operators can always join. If the file doesn’t exist, Netherrack creates an empty one.

whitelist.json (the identifiers are just examples) 
[
  {
    "name": "SchleroMC",
    "xuid": "2535400000000000",
    "uuid": "11111111-2222-3333-4444-555555555555"
  },
  { "name": "AnOfflineFriend" }
]

Use /whitelist to add and remove players, list entries, reload hand edits, or turn the whitelist on and off. The disconnect reason comes from messages.server-whitelist in netherrack.yml.

banned-players.json

The player ban list, kept in the same shape Cloudburst Nukkit uses: each entry has a lowercase name, creation date, source, expireDate and reason. Netherrack also saves the XUID and UUID of an online target, so a ban survives a gamertag change; an offline player can be banned by name alone. A date in expireDate makes the ban lift itself once it passes, while Forever is permanent. If the file doesn’t exist, Netherrack creates an empty one.

banned-players.json (the identifiers are just examples) 
[
  {
    "name": "griefer",
    "xuid": "2535400000000000",
    "uuid": "11111111-2222-3333-4444-555555555555",
    "creationDate": "2026-11-21 20:30:00 +0000",
    "source": "SchleroMC",
    "expireDate": "Forever",
    "reason": "griefing the spawn"
  }
]

Use /ban to add a ban, /pardon (or /unban) to remove one, and /banlist to list bans or reload the file after a hand edit. Nukkit’s /banlist ips is accepted too, but Netherrack doesn’t keep IP bans. The disconnect reason comes from messages.server-ban in netherrack.yml, with the stored reason appended.

players/

Netherrack keeps a small identity record for every player it has seen in one JSON file named after that player’s UUID, following Nukkit’s UUID-based players/ layout. The plugin API’s Server.getOfflinePlayer(...) methods read this index along with online players and the existing permission, whitelist, ban and world data. Inventories and positions are not duplicated here.

players/11111111-2222-3333-4444-555555555555.json (the ids are examples) 
{
  "name": "SchleroMC",
  "uuid": "11111111-2222-3333-4444-555555555555",
  "xuid": "2535400000000000",
  "firstPlayed": 1761000000,
  "lastPlayed": 1764000000
}

The timestamps are Unix seconds. The xuid key is omitted for offline/self-signed logins, and older imported records may omit uuid too. If an old player-identity.json is present at startup, Netherrack imports it into players/ once and then removes it.

Language

The language setting controls the console’s own messages: en-US (English) or pt-BR (Brazilian Portuguese). Players see the game itself in whatever language their client uses. To change it, edit the value and restart. Translations are ordinary .properties files in the project’s lang folder.
